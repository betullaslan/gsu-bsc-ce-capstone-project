Classify the following Gherkin scenario and return ONLY valid JSON.

Allowed labels:

test_level:
- Unit
- Integration
- System
- Acceptance

test_type:
- Functional
- Regression
- End-to-End
- Error Handling
- Performance
- Security

Definitions:

test_level:
- Unit: tests a single isolated function, parser, validator, resolver, or component without running the real application.
- Integration: mainly tests a specific mechanism, boundary, or interaction between components/modules/resources. Examples include ID resolution, dependency resolution, serialization, persistence behavior, or command behavior over stored ticket data.
- System: runs the real application through a public interface such as CLI, API, or UI and checks externally visible behavior.
- Acceptance: validates a complete user/business goal, meaningful user journey, or acceptance-level requirement.

test_type:
- Functional: normal expected behavior.
- Error Handling: invalid input, missing data, failed command, exception, or error message.
- End-to-End: complete workflow with multiple meaningful user actions from setup to final outcome.
- Security: authentication, authorization, permissions, secrets, injection, or sensitive data.
- Performance: speed, latency, load, scalability, or resource usage.
- Regression: explicitly mentions or clearly targets a previous bug, fixed behavior, regression prevention, safety, or preventing breakage.

Classification rules:
- Choose the MAIN purpose of the scenario.
- Do not choose Integration only because files, stored tickets, dependencies, links, notes, or application state are involved.
- Choose Integration when the main purpose is a specific mechanism, boundary, or interaction rather than general application behavior.
- Choose System when the main purpose is externally visible behavior of the real application through CLI, API, or UI.
- Do not choose Acceptance only because the scenario is written from the user's perspective.
- Choose Acceptance only for a meaningful user/business goal, workflow, or acceptance-level requirement.
- Scenario name, Feature, Background, and Steps are all part of the scenario content.
- Use only the provided scenario content.

Output rules:
- Output ONLY valid JSON.
- Output MUST be a single JSON object.
- Keys MUST be exactly: "test_level", "test_type".
- Values MUST be selected only from the allowed labels.
- Do not output explanations, markdown, Unknown, null, empty strings, or extra keys.

Output format:
{"test_level":"System","test_type":"Functional"}

Input scenario:

Scenario name:
$scenario_name

Feature:
$feature

Background:
$background

Steps:
$steps
